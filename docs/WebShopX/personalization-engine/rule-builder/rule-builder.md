# Rule Builder - Создание правил персонализации

*Система создания гибких правил персонализации с триггерами времени, сегментов и поведения*

---

## 🎯 Обзор Rule Builder

Rule Builder - это мощный инструмент для создания сложных правил персонализации, которые автоматически активируются на основе различных триггеров. Система позволяет создавать индивидуальные предложения для каждого игрока в зависимости от его поведения, характеристик и времени.

### Основные возможности:
- **Создание правил** - настройка условий и триггеров
- **Триггеры времени** - активация по расписанию и событиям
- **Сегментные триггеры** - правила для определенных групп игроков
- **Поведенческие триггеры** - реакция на действия игроков

---

## ⚙️ Типы триггеров

### 🕐 Временные триггеры
- **Расписание** - активация в определенное время/день
- **Сезонность** - правила для праздников и событий
- **Интервалы** - повторяющиеся активации
- **Сроки** - ограниченное время действия

### 👥 Сегментные триггеры
- **География** - правила по странам/регионам
- **RFM анализ** - Recency, Frequency, Monetary
- **ARPU сегменты** - по доходности игроков
- **Риск оттока** - правила для удержания

### 🎮 Поведенческие триггеры
- **Игровые действия** - реакции на поведение в игре
- **Покупки** - правила на основе транзакций
- **Активность** - время игры, частота заходов
- **Социальные** - взаимодействие с другими игроками

---

## 🎯 Сценарии использования Rule Builder

### **Сценарий 1: "Создание правила для новых игроков"**
*Как настроить автоматическое предложение для новичков*

**Что происходит:**
1. **Создание правила:**
   - Триггер: "Игрок зарегистрировался менее 7 дней назад"
   - Условие: "Не совершал покупок"
   - Действие: "Предложить скидку 50% на первый скин"

2. **Настройка условий:**
   - Сегмент: "Новые игроки"
   - География: "Все регионы"
   - Время: "Активировать через 2 дня после регистрации"

3. **Результат:**
   - Автоматическая отправка персонализированного предложения
   - Отслеживание конверсии
   - Анализ эффективности правила

**📊 Какие данные используются:**
- **👥 Данные об игроках** - дата регистрации, история покупок
- **🎯 Данные о сегментах** - классификация игроков
- **📈 Данные о продажах** - для анализа эффективности

### **Сценарий 2: "Правило для игроков с высоким риском оттока"**
*Как создать правило для удержания неактивных игроков*

**Что происходит:**
1. **Анализ поведения:**
   - Игрок не заходил в игру 14+ дней
   - Ранее был активным покупателем
   - Риск оттока: высокий (по ML модели)

2. **Создание правила:**
   - Триггер: "Высокий риск оттока"
   - Условие: "Был активным покупателем"
   - Действие: "Отправить персональное предложение"

3. **Персонализация:**
   - Анализ любимых категорий товаров
   - Создание эксклюзивного предложения
   - Отправка через email + push-уведомление

**📊 Какие данные используются:**
- **🤖 ML модели** - предсказание риска оттока
- **👥 Данные об игроках** - история активности и покупок
- **📊 Аналитические данные** - поведенческие паттерны

### **Сценарий 3: "Сезонное правило для праздников"**
*Как настроить автоматические акции на праздники*

**Что происходит:**
1. **Планирование сезонности:**
   - Анализ популярности контента в прошлые праздники
   - Определение целевых сегментов
   - Создание тематических предложений

2. **Настройка временного триггера:**
   - Дата активации: "1 декабря"
   - Длительность: "31 день"
   - Повторение: "Ежегодно"

3. **Сегментирование:**
   - Активные игроки из холодных регионов
   - Покупатели зимнего контента
   - Игроки с высоким LTV

**📊 Какие данные используются:**
- **📅 Временные данные** - календарь событий и праздников
- **🌍 Географические данные** - сезонность по регионам
- **📈 Исторические данные** - эффективность прошлых кампаний

## 📋 Модели данных Rule Builder

### ⚙️ Данные о правилах персонализации

**Что хранится:**
- **Название правила** - "Новичкам скидка 50%"
- **Тип триггера** - время, сегмент, поведение
- **Условия активации** - детальные параметры
- **Действия** - что происходит при срабатывании
- **Статистика** - эффективность и использование

**Пример данных:**
```
Правило: "Winter_Skins_Newbies"
Тип: "Комбинированный (время + сегмент)"
Триггеры:
  - Время: "1-31 декабря"
  - Сегмент: "Новые игроки (регистрация < 30 дней)"
  - Поведение: "Не покупал скины"
Действия:
  - Email: "Персональное предложение"
  - Push: "Уведомление в игре"
  - Предложение: "Скидка 50% на зимние скины"
Статистика:
  - Активаций: "2,847"
  - Конверсия: "23.5%"
  - Доход: "$12,450"
```

**Как используется:**
- Для автоматической персонализации предложений
- Для A/B тестирования различных правил
- Для оптимизации маркетинговых кампаний
- Для анализа эффективности персонализации

### 🎯 Данные о триггерах и условиях

**Что хранится:**
- **Тип триггера** - время, сегмент, поведение
- **Параметры** - конкретные значения и условия
- **Приоритет** - порядок выполнения правил
- **Активность** - включено/выключено
- **Логи** - история срабатываний

**Пример данных:**
```
Триггер: "Временной"
Параметры:
  - Тип: "Повторяющийся"
  - Интервал: "Еженедельно"
  - День: "Понедельник"
  - Время: "10:00 UTC"
Условия:
  - Сегмент: "Активные игроки"
  - Минимальный уровень: "10"
  - Последняя активность: "< 7 дней"
Приоритет: "Высокий"
```

**Как используется:**
- Для планирования автоматических кампаний
- Для управления приоритетами правил
- Для отладки и мониторинга системы
- Для анализа частоты срабатываний

### 📊 Данные об эффективности правил

**Что хранится:**
- **Статистика активаций** - сколько раз сработало
- **Конверсия** - процент положительных реакций
- **Доходность** - финансовые результаты
- **Сегментация** - эффективность по группам
- **Временные тренды** - изменение эффективности

**Пример данных:**
```
Правило: "High_Value_Retention"
Период: "Январь 2024"
Активаций: "1,247"
Конверсия: "34.2%"
Доход: "$45,670"
ARPU: "$36.60"
Сегменты:
  - VIP игроки: "45% конверсия"
  - Премиум: "28% конверсия"
  - Стандарт: "12% конверсия"
```

**Как используется:**
- Для оптимизации существующих правил
- Для создания новых правил на основе успешных
- Для ROI анализа персонализации
- Для планирования бюджета на кампании

- **Real-time мониторинг** - отслеживание активности правил
- **Детальная аналитика** - эффективность по всем метрикам
- **A/B тестирование** - сравнение вариантов правил

### Интеграции

## 📈 Ключевые метрики Rule Builder

### Метрики правил
- **Количество активных правил** - общее число работающих правил
- **Частота срабатываний** - среднее количество активаций в день
- **Конверсия правил** - процент успешных срабатываний
- **Время выполнения** - скорость обработки правил

### Эффективность персонализации
- **Personalization Rate** - процент персонализированных предложений
- **Targeting Accuracy** - точность попадания в цель
- **Response Rate** - процент откликов на персонализированные предложения
- **Revenue Impact** - влияние персонализации на доходы

### Операционные метрики
- **Rule Creation Time** - время создания нового правила
- **Testing Coverage** - процент протестированных правил
- **Error Rate** - процент ошибок в работе правил
- **System Uptime** - время работы системы без сбоев
